## Как представить работу за две минуты

«Я продолжила Assignment 5: сохранила Person, Student, Teacher, Doctor, Hospital, ExamResult и выплаты через Payable. Общий массив людей заменён HashMap с поиском по ID. Для группировки по ролям использую EnumMap с наборами Set, для истории экзаменов - ArrayList, а для врачей больницы - LinkedHashSet. Заявки на выплату поступают в PriorityQueue. Сначала обрабатывается HIGH, затем MEDIUM и LOW; внутри одного приоритета сохраняется порядок подачи. CRUD согласованно очищает индексы, связи и очередь. Программа работает в памяти, выплаты моделируются».

## Вопросы и ответы

**Зачем equals и hashCode?** Они определяют логическую идентичность сущностей. Два объекта Person с одинаковым ID считаются одним человеком. У равных объектов должен быть одинаковый хеш. Иначе HashSet/HashMap могут неправильно определять совпадения.

**Почему ID final?** Если изменить поле, по которому считается хеш, уже добавленный объект может оказаться не в той хеш-корзине. Изменение имени или города безопасно: эти поля в хеше не участвуют. Разные подклассы Person используют единое пространство ID.

**equals и == - одно и то же?** Нет. == сравнивает ссылки. equals сравнивает бизнес-ключ. При работе сервиса связанные коллекции содержат тот же канонический объект, поэтому обновление его имени видно и в больнице.

**Почему Comparable по ID?** Это естественный стабильный порядок, согласованный с equals: compareTo == 0 тогда и только тогда, когда совпадают ID. Строки сравниваются лексикографически, поэтому используются ID с ведущими нулями.

**Зачем ещё Comparator?** Для разных представлений: по имени, возрасту и выплате. При совпадении основного критерия сравнивается ID. Эти компараторы используются для временных списков, а не для хранения изменяемых объектов в TreeSet.

**HashMap всегда O(1)?** Нет. Для get/put обычно ожидается O(1) при хорошем распределении ключей. Фильтрация по произвольному условию требует прохода по данным. Полное удаление дороже, потому что нужно очистить связи.

**Почему не хранить одновременно общий List, Set и Map людей?** Это дублировало бы реестр без необходимости. Основной реестр - Map; отдельные Set нужны для индекса ролей. Отсортированный List создаётся по запросу. List/Set также используются в связях доменных объектов.

**Почему PriorityQueue, а не обычная FIFO-очередь?** У выплат есть приоритет. FIFO соблюдается только среди одинаковых приоритетов благодаря sequence. HIGH всегда предшествует MEDIUM и LOW.

**Что возвращает poll при пустой очереди?** null. В сервисе перед обработкой используется peek; если он возвращает null, метод возвращает Optional.empty. После расчёта суммы poll удаляет обработанную заявку.

**Почему нельзя просто вывести PriorityQueue циклом?** Её итератор не гарантирует порядок приоритетов. Для отображения создаётся и сортируется копия. offer/poll имеют O(log q), но вся подача заявки дополнительно проверяет дубликат среди запросов и поэтому имеет O(r).

**Что будет при удалении врача?** Он исчезнет из Map по ID, набора своей роли, всех больниц, очереди и реестра связанных заявок. Остальные врачи и больницы сохранятся.

**Композиция и агрегация?** Student создаёт и хранит ExamResult: это композиция. Hospital хранит ссылки на независимо созданных Doctor: это агрегация. Один врач может состоять в нескольких больницах, а одна больница иметь многих врачей.

**Где зависимость от интерфейса?** PayrollService.pay принимает Payable. Конкретная формула выбирается полиморфно: стипендия студента, зарплата преподавателя с надбавкой или доход врача.

**Что значит синхронный CRUD?** В этой работе - согласованное обновление всех коллекций. Программа однопользовательская. Ключевое слово synchronized и потокобезопасность для этого задания не заявлены.

**Как обрабатываются ошибки?** Модель проверяет значения и выбрасывает исключения, а Main показывает понятное сообщение и возвращается в меню. При ошибке составного обновления контактных данных старые значения полностью сохраняются.

**Почему long для выплат?** Чтобы умножение зарплаты на стаж и расчёт дохода не переполняли int. Учебные суммы представлены в целых USD, как в Assignment 5; для полноценной финансовой системы правила были бы другими.

**Что происходит с данными после выхода?** Они исчезают. База данных не требовалась. При следующем запуске снова загружаются демонстрационные записи.
